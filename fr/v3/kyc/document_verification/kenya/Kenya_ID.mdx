Vérifiez la carte de national ID kényane d'un client en téléversant une photo — aucune saisie manuelle de l'ID requise. Extraction OCR plus une concordance faciale requise par rapport à un selfie — pas de vérification de vivacité (pas de vidéo, pas de défi de clignement/mouvement).

<Note>
  Il s'agit d'un document recto-verso — fournissez à la fois `document_front` et `document_back` pour l'extraction la plus complète. Le Kenya a deux générations de cartes d'identité en circulation : l'ancien design plastifié et le nouveau « Maisha Card ». Les champs spécifiques à la Maisha Card (`serial_number`, `place_of_issue`, date d'expiration) reviendront vides sur une carte plus ancienne — c'est attendu, pas une erreur.
</Note>

<Note>
  `selfie_image` est requis — le visage extrait du document est comparé à celui-ci. Il s'agit d'une comparaison d'image fixe (pas de vivacité).
</Note>

## Endpoint

```
POST /api/onboarding/document_verification/kenya/kenya_id
```

## Requête

### En-têtes

| En-tête | Valeur | Requis |
|--------|-------|----------|
| `x-access-token` | Votre clé secrète API | Oui |
| `Content-Type` | `multipart/form-data` | Oui |

### Paramètres de corps

| Paramètre | Type | Requis | Description |
|-----------|------|----------|--------------|
| `document_front` | file | Oui | Recto de la carte d'identité. JPG ou PNG, max 5 Mo |
| `document_back` | file | Non | Verso de la carte d'identité. JPG ou PNG, max 5 Mo |
| `selfie_image` | file | Oui | Un selfie à comparer avec la photo du visage du document. JPG ou PNG, max 5 Mo |

### Exemple

<CodeGroup>
```bash cURL
curl -X POST "https://adhere-api.smartcomply.com/api/onboarding/document_verification/kenya/kenya_id" \
  -H "x-access-token: YOUR_SECRET_KEY" \
  -F "document_front=@/path/to/id_front.jpg" \
  -F "document_back=@/path/to/id_back.jpg" \
  -F "selfie_image=@/path/to/selfie.jpg"
```

```javascript Node.js
const formData = new FormData();
formData.append("document_front", fs.createReadStream("/path/to/id_front.jpg"));
formData.append("document_back", fs.createReadStream("/path/to/id_back.jpg"));
formData.append("selfie_image", fs.createReadStream("/path/to/selfie.jpg"));

const response = await fetch(
  "https://adhere-api.smartcomply.com/api/onboarding/document_verification/kenya/kenya_id",
  {
    method: "POST",
    headers: { "x-access-token": "YOUR_SECRET_KEY" },
    body: formData,
  }
);
const data = await response.json();
```

```python Python
import requests

response = requests.post(
    "https://adhere-api.smartcomply.com/api/onboarding/document_verification/kenya/kenya_id",
    headers={"x-access-token": "YOUR_SECRET_KEY"},
    files={
        "document_front": open("/path/to/id_front.jpg", "rb"),
        "document_back": open("/path/to/id_back.jpg", "rb"),
        "selfie_image": open("/path/to/selfie.jpg", "rb"),
    },
)
data = response.json()
```
</CodeGroup>

## Réponse

### 200 OK

| Champ | Type | Description |
|-------|------|--------------|
| `status` | string | `"success"` en cas d'extraction réussie |
| `data.full_name` | string | Nom complet extrait |
| `data.first_name` | string | Prénom extrait |
| `data.last_name` | string | Nom de famille extrait |
| `data.date_of_birth` | string | Date de naissance au format `YYYY-MM-DD` |
| `data.gender` | string | Genre extrait |
| `data.id_number` | string | Le numéro d'identité |
| `data.document_type` | string | `"kenya_id"` |
| `data.expiry_date` | string | Date d'expiration de la Maisha Card — présente uniquement sur les cartes de troisième génération |
| `data.issue_date` | string | Date de délivrance |
| `data.place_of_issue` | string | Présent uniquement sur les IDs « Maisha Card » de troisième génération |
| `data.serial_number` | string | Numéro de série distinct à 9 chiffres — présent uniquement sur les IDs « Maisha Card » de troisième génération |
| `data.photo` | string | Photo du visage extraite du document, encodée en base64 |
| `data.extra_fields` | object | Autres champs imprimés sur la carte — voir ci-dessous |
| `data.face_match` | object | Résultat de la comparaison du visage du document avec `selfie_image` — voir ci-dessous |
| `data.face_match.attempted` | boolean | Si une comparaison a réellement été exécutée |
| `data.face_match.verified` | boolean \| null | `true`/`false` si la comparaison a été exécutée ; `null` si elle ne l'a pas pu (voir Notes de concordance faciale) |
| `data.face_match.confidence_percentage` | number | Confiance de correspondance, 0–100 |
| `data.face_match.selfie_image` | string | URL du selfie téléversé |
| `message` | string | Résumé du résultat lisible par l'homme |

<Note>
  **Champs additionnels** — `extra_fields` porte tout ce que la carte a imprimé au-delà des champs listés ci-dessus : `district_of_birth`, et — uniquement lorsque `document_back` a été fourni — `district`, `division`, `location`, `sub_location`, `barcode_number`, et les trois lignes MRZ (`mrz_line1`/`mrz_line2`/`mrz_line3`, exactement telles qu'imprimées, y compris les caractères de remplissage `<` — non décodées). Seuls les champs réellement présents sur la carte sont inclus.
</Note>

<Note>
  **Notes de concordance faciale** — si le service de comparaison lui-même échoue, `attempted` reflète si une comparaison a réellement été exécutée et `verified` revient `null` avec un champ `reason` expliquant pourquoi — c'est différent de `verified: false`, qui signifie que la comparaison a été exécutée et que les visages ne correspondaient pas. Un problème de concordance faciale ne bloque jamais les données du document sous-jacent — le reste de `data` est toujours renvoyé.
</Note>
