L'endpoint NIN récupère les données d'identité vérifiées d'un client depuis la base de données de la National Identity Management Commission (NIMC). Il renvoie des détails personnels complets incluant les données biographiques, les informations de contact de proche et une photo du client.

## Endpoint

```
POST /api/onboarding/nigeria_kyc/nin/
```

## Requête

### En-têtes

| En-tête | Valeur | Requis |
|--------|-------|----------|
| `x-access-token` | Votre clé secrète API | Oui |
| `Content-Type` | `application/json` | Oui |

### Paramètres de corps

| Paramètre | Type | Requis | Description |
|-----------|------|----------|-------------|
| `identification_number` | string | Oui | Le Numéro National d'Identification à 11 chiffres du client |
| `reverify` | boolean | Non | `true` récupère à nouveau ce NIN auprès du NIMC au lieu de l'enregistrement conservé par Adhere. Par défaut `false`. Voir la section Revérification ci-dessous. |

### Exemple

<CodeGroup>
```bash cURL
curl -X POST "https://adhere-api.smartcomply.com/api/onboarding/nigeria_kyc/nin/" \
  -H "x-access-token: YOUR_SECRET_KEY" \
  -H "Content-Type: application/json" \
  -d '{"identification_number": "70123456789"}'
```

```javascript Node.js
const response = await fetch(
  "https://adhere-api.smartcomply.com/api/onboarding/nigeria_kyc/nin/",
  {
    method: "POST",
    headers: {
      "x-access-token": "YOUR_SECRET_KEY",
      "Content-Type": "application/json",
    },
    body: JSON.stringify({ identification_number: "70123456789" }),
  }
);
const data = await response.json();
```

```python Python
import requests

response = requests.post(
    "https://adhere-api.smartcomply.com/api/onboarding/nigeria_kyc/nin/",
    headers={
        "x-access-token": "YOUR_SECRET_KEY",
        "Content-Type": "application/json",
    },
    json={"identification_number": "70123456789"},
)
data = response.json()
```
</CodeGroup>

## Revérification

Adhere répond à une nouvelle vérification du même NIN à partir de l'enregistrement conservé la première fois. Si les informations du client ont changé depuis auprès du NIMC (par exemple après un changement de nom), envoyez `"reverify": true` pour récupérer à nouveau l'enregistrement auprès du NIMC.

- La vérification est facturée au prix normal du NIN.
- Le nouvel enregistrement remplace celui conservé : les vérifications suivantes de ce NIN renvoient les informations actuelles.
- Si le NIMC n'a plus l'enregistrement, vous recevez une réponse « introuvable » et l'enregistrement conservé n'est plus utilisé.

```json
{
  "identification_number": "70123456789",
  "reverify": true
}
```

La même action existe dans le tableau de bord : ouvrez le menu de la vérification NIN dans Onboarding Suite → Identité et choisissez **Revérifier**.

### 400 Bad Request

Renvoyé lorsque le NIN est manquant, malformé ou introuvable.

```json
{
  "status": "failed",
  "data": [],
  "message": "Sorry, your check cannot be processed at the moment. Please try again in a few minutes"
}
```

#### Erreurs de revérification

| Cas | `message` |
|-----|-----------|
| `reverify` n'est ni `true` ni `false` | `reverify must be true or false` |
| Le type d'identifiant ne peut pas être revérifié (renvoie aussi `"code": "REVERIFY_NOT_AVAILABLE"`, rien n'est facturé) | `Reverification isn't available for this ID type.` |
| Le NIMC est injoignable (`data.error_code` vaut `PROVIDER_UNAVAILABLE`) | `The verification service is unavailable right now, so this ID wasn't reverified. Please try again in a few minutes.` |
| Le NIMC répond que le NIN est invalide ou introuvable | La raison donnée par le NIMC, par exemple `Invalid NIN` |

```json
{
  "status": "failed",
  "data": { "error_code": "PROVIDER_UNAVAILABLE" },
  "message": "The verification service is unavailable right now, so this ID wasn't reverified. Please try again in a few minutes."
}
```
